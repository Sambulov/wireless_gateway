# Инструменты карт регистров Modbus

Единый формат описания приборов — `modbus-regmap/1.0`, спецификация рядом:
[`FORMAT.md`](FORMAT.md). Старых форматов и конвертеров в проекте нет.

Карты живут **в одном месте** — `main/flash_data/regmaps/*.jsonc`: это содержимое
файловой системы устройства, оно же источник правды в репозитории. Никаких копий.

```bash
cd /home/dmitry/Projects/wireless_gateway

# Проверить карту или все сразу: схема, типы, все перекрёстные ссылки
python3 tools/regmap/validate.py main/flash_data/regmaps/*.jsonc

# Починить пропущенные запятые в рукописном файле (висячие разбираются и так)
python3 tools/regmap/jsonc.py --fix main/flash_data/regmaps/новая_карта.jsonc

# После правки — пересобрать и прошить, файловая система собирается в образ
idf.py build && idf.py -p /dev/ttyUSB0 flash
```

| Файл | Назначение |
|---|---|
| `FORMAT.md` | спецификация формата `modbus-regmap/1.0` |
| `jsonc.py` | чтение/запись JSONC (комментарии, висячие запятые), починка пропущенных запятых |
| `validate.py` | проверка по схеме и всех ссылок между регистрами |

## Интерпретатор

Универсальная страница работы с приборами лежит в `main/flash_data/modbus.html`
(в файловой системе устройства, правится через файловый менеджер без перепрошивки)
и открывается по адресу **`/modbus`** (алиас на `/modbus.html`).

Что умеет:

- выбирает карту из `/regmaps/*.jsonc`, читает её прямо из файловой системы;
- параметры связи (адрес, скорость, чётность, стоп-биты) берёт из карты и
  применяет их к UART шлюза, после чего сама начинает опрос;
- декодирует все типы формата: целые и дробные, строки, BCD, битовые поля,
  составные (дата/время), перечисления, ссылки `enum_from`, динамические границы;
- опрашивает видимую группу, аварии и вынесенное в `ui`; класс `poll` задаёт
  частоту (fast — каждый такт, остальные — реже); диапазоны нарезаются по
  `limits.max_regs_per_read` и идут по кругу;
- пишет регистры с доступом «чтение/запись» (FC6 / FC16), регистры с
  `write.mode: command` помечает как «только командой»;
- выполняет команды из карты (последовательности записей).

Разработку удобно вести так: правите `main/flash_data/modbus.html`, заливаете файл
через файловый менеджер (`/config` → «Файлы») и обновляете страницу — перепрошивка
не нужна.

## Что стоит помнить

- Прибор **не всегда отвечает на большие запросы**: у INNOVERT ISD предел 16 регистров
  за один FC3 — это записано в `transport.limits.max_regs_per_read`.
- Порядок слов (`byte_order`) обязателен для многорегистровых величин: у SUTO S111 это
  `ABCD` (big-endian, IEEE 754 ABCD), но многие приборы используют `CDAB`.
- `value.scale` — **множитель**: «делить на 10» записывается как `0.1`.
- `default` задаётся в **инженерных единицах**: при записи интерпретатор считает
  `raw = (default − offset) / scale`.
- Интерпретатор читает карты с устройства: `http://<ip>/regmaps/<файл>.jsonc`.
